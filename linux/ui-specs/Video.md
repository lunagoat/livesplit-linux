# Video
Toolkit-free VideoSettings. Single three-row group, no tabs or tooltips.
1. “Video Path:” editable textbox -> VideoPath, immediate edits; “Browse...” single file picker, filter “Video Files|*.avi;*.mpeg;*.mpg;*.mp4;*.mov;*.wmv;*.m4v;*.flv;*.mkv;*.ogg|All Files (*.*)|*.*”. Initialize to existing resolved file directory/name. File drop uses first path, commits immediately.
2. “Run Starts At:” right-aligned time textbox -> OffsetString (Offset), commit on validation/focus loss. Accept digits, colon, comma, dot, minus; invalid input leaves offset unchanged. Default zero; ShortTimeFormatter display.
3. Size slider -> SizeValue; label SizeLabel (“Width:” in horizontal mode, “Height:” otherwise). Minimum 100, maximum SizeMaximum (400 horizontal / 300 vertical), step 1, no ticks. Width and Height default 200; the unselected dimension stays persisted. Mode updates size bindings and labels immediately. No enable/visibility dependencies.
XML version 1.4, VideoPath/Offset/Height/Width unchanged. Mode is runtime only. MRL is a computed file URI; paths resolve through Core PathCompat only when used.
Linux playback uses an external muted mpv window, starts at run real time plus Offset, pauses/resumes via JSON IPC, seeks on Synchronize, and stops on reset/disposal/deactivation. Negative start positions clamp to zero. Embedding in the timer layout is deferred: the old ActiveX rendering cannot be preserved without a toolkit-specific native surface. Component reserves no layout area until embedding exists; stored dimensions remain available for the future view. No legacy hidden settings beyond the inactive dimension.
The removed ComponentHostForm was a resource-only “Form1” (284×262) containing an enabled VLC ActiveX surface (320×240 at 77,42); it exposed no settings or user actions. Its OcxState resource is obsolete with external mpv playback.
